# Lessons Learned

- **Mathematical Theater ("Mathiness"):** It is surprisingly easy to "prove" profound philosophical statements in formal verification systems (like Lean) by burying the actual physical claims inside type definitions or class properties. For example, proving that a rigid hardware system fails resonance by simply defining it as having a fixed capacity $C$ while the environment requires $C+1$ is trivial, not rigorous.
- **Honest Postulates over Trivial Proofs:** If a mathematical phenomenon (e.g., the stability of the Kuramoto ODE in a critical network, or the topological defect mapping via homotopy groups) is beyond the immediate capacity of the current Mathlib ecosystem, it must be stated explicitly as a physical postulate using `axiom`. Inventing a trivial class with properties like `monotone` and `bounded` to satisfy the compiler via the Monotone Convergence Theorem creates the illusion of rigor where none exists.
- **Bridging the Semantic Gap:** Physical formalization requires mapping semantic concepts (like "Boundary") to rigorous mathematical objects (like continuous maps without null-homotopy). Merely applying the Intermediate Value Theorem and *calling* the intermediate point a "Topological Defect" is semantic sleight of hand.
